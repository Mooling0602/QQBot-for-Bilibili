# 直播通知实现计划

> 状态：已实现，待部署配置启用。

## 目标与范围

`live_alert` 向启用该功能并订阅某个 MID 的 QQ 群发送 UP 主开播通知，并可按群配置发送下播通知。它不依赖动态截图服务。

常规订阅必须适用于任意可查询的 MID，因此使用 `bilibili-feed-api` 的
`get_live_status(client, mid)`。该 API 只负责读取和标准化状态；QQBot 负责轮询、状态持久化、群配置和消息投递。只有检测到需要投递的开播事件时，QQBot 才调用 `get_live_room_info(client, room_id)` 获取分区和开播时间。

## 通知语义

- `liveStatus` 为 `0`（未开播）或 `2`（轮播）后变为 `1`（直播中）时，产生一条开播事件。
- 同一场直播以 `room_id` 和 `live_time` 组成的会话标识去重；已推送的群不会因后续轮询重复收到消息。
- 首次观察 MID、首次升级旧配置，或某个群刚订阅 MID 时，只建立基线。此时即使主播已经直播，也不补发历史提醒。
- 同一 MID 被多个群订阅时只查询一次，再向符合订阅时间条件的群分别投递。
- 开播消息为“提示词 + 直播标题 + 分区（若有）+ 开播时间（若有）+ 直播间直链（`add_url` 开启时）”。不使用截图或封面图。
- 详情查询失败时，立即用状态接口已取得的标题发送开播消息；该详情请求随后独立退避重试，且不会重复开播消息。
- `notify_on_close: true` 的群会收到下播消息，但前提是该群已成功收到本场开播消息且仍订阅该 MID。下播消息使用缓存的直播详情和本地检测到的下播时间，不额外请求详情接口。

## 轮询与失败处理

- 正常间隔为每个 MID 每秒一次。
- 同一 MID 使用异步锁串行查询；不同 MID 可并行，但所有请求共享每秒 10 次的全局令牌桶，并均匀调度，避免订阅数量增加后形成整秒突发请求。
- 单个 MID 状态查询失败时按 `1 -> 2 -> 4 -> 8 -> 16 -> 32 -> 64` 秒指数退避，并加入少量随机抖动；任意一次成功查询立即恢复 1 秒间隔。详情查询失败使用相同上限，但不延缓状态轮询。
- 失败不覆盖最后一次成功状态，也不产生开播或下播事件。连续失败期间可能延迟通知；若主播在故障窗口内开播并下播，则无法由轮询补获。
- 运行前的服务器实测为 300 次、5 分钟、每秒一次查询均成功，P50 45.4 ms、P95 87.2 ms。该结果只证明当前出口短期可用，不视为长期风控上限。

## 配置与状态兼容

现有 `features.yml` 的 `live_alert.enable`、`mids`、`prompt` 和 `add_url` 保持兼容。根配置新增独立的 `live_monitor` 总开关，默认关闭；不能因启用动态监听而自动启动直播轮询。`notify_on_close` 和 `prompt_on_close` 是新增的直播群级选项，默认关闭和空提示词。

群配置需要把目前仅为 `dynamic_push` 实现的 `mid_subscribed_at` 机制泛化给 `live_alert`。旧群配置在首次扫描时按当前时间补齐订阅时间，移除 MID 时同时清理对应时间。

直播状态单独保存在 `cache/live_<mid>.json`，与动态的 `seen_<mid>.json` 隔离。缓存至少保存最后一次成功状态、当前会话标识、待重试详情和群级投递记录，并以原子写入更新。下播待投递会话保留为队列，即使 OneBot 在多场直播间暂不可用也不会被新会话覆盖。只有群消息发送成功或明确进入终态忽略后，才记录该群已投递，避免发送失败后丢失通知或对其他群重复通知。

主机器人保持 `config.yml` 和 `features.yml` 只读挂载。版本升级时由 `python -m qqbot.core.updater` 在短生命周期、可写挂载整个部署目录的容器中执行；它只添加缺失项、保留首次 `.bak` 备份且可重复执行。部署编排必须在迁移成功后才启动新主容器，因此后续配置结构升级不需要用户手动补字段。

## 官方主播授权通道

普通订阅没有可用于任意 UP 主的官方主动通知接口。对于愿意自行授权的主播，可另行实现直播开放平台提供方：开发者应用通过自身 `app_id`、应用密钥和主播给出的 `room_owner_auth_code` 建立官方 WebSocket 会话，接收开播和下播事件。

该通道只能覆盖授权房间，必须作为普通 MID 轮询之外的独立提供方。应用密钥和授权码只能从部署侧运行时机密读取，不能存入群配置、命令参数、缓存或日志。接入要求以 [Bilibili 直播开放平台文档](https://open-live.bilibili.com/document/657d8e34-f926-a133-16c0-300c1afc6e6b) 为准。
